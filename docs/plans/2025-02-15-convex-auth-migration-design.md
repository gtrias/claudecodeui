# Convex Auth Migration Design

**Date:** 2025-02-15  
**Status:** Approved  
**Scope:** Replace Express/SQLite/JWT authentication with Convex Auth + Email OTP via Resend

---

## Overview

Migrate user authentication from the current Express + SQLite + JWT stack to Convex Auth with Email OTP, as the first step in a gradual migration to Convex.

### Goals

- Replace username/password auth with passwordless Email OTP
- Use Convex Auth for session management
- Use Resend for OTP email delivery (onboarding mode, no domain required)
- Maintain existing UI styling and i18n support
- Keep Express server for non-auth functionality (files, terminal, etc.)

### Non-Goals

- Migrating other data to Convex (settings, projects, etc.) - future work
- Supporting multiple auth providers (OAuth, SMS) - future work
- Migrating existing users - fresh start approved

```
│  │ (email input)│  │ (code input)│  │ (wraps app)             │  │
│  └──────┬──────┘  └──────┬──────┘  └───────────┬─────────────┘  │
│         │                │                     │                │
│         └────────────────┼─────────────────────┘                │
│                          │                                      │
└──────────────────────────┼──────────────────────────────────────┘
                           │ Convex React Client
                           ▼
┌──────────────────────────────────────────────────────────────────┐
│                      Convex Backend                              │
│  ┌────────────────┐  ┌────────────────┐  ┌───────────────────┐  │
│  │ auth.config.ts │  │ auth functions │  │ users table       │  │
│  │ (OTP + Resend) │  │ (sign in/out)  │  │ (Convex DB)       │  │
│  └───────┬────────┘  └────────────────┘  └───────────────────┘  │
│          │                                                       │
└──────────┼───────────────────────────────────────────────────────┘
           │
           ▼
┌──────────────────┐
│  Resend API      │
│  (sends OTP      │
│   emails)        │
└──────────────────┘
```

**Key Points:**
- Convex replaces Express auth endpoints + SQLite user storage
- Existing Express server remains for file operations, terminal, etc.
- `ConvexAuthProvider` wraps the app, coexists with existing providers
- OTP codes sent via Resend, verified by Convex

## Authentication Flow

### OTP Sign-In Flow

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   Step 1     │     │   Step 2     │     │   Step 3     │
│  Email Input │────▶│  OTP Sent    │────▶│  Code Input  │
│              │     │  (waiting)   │     │              │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
                     ┌──────────────┐             │
                     │   Step 4     │◀────────────┘
                     │ Authenticated│
                     │  (redirect)  │
                     └──────────────┘
```

### User Journey

1. **Email Entry** → User enters email in `OTPLoginForm`
2. **Send OTP** → Convex calls Resend API, sends 6-digit code
3. **Code Entry** → User enters code in `OTPVerifyForm`
4. **Verification** → Convex validates code, creates session
5. **Authenticated** → User redirected to main app, session stored

### Session Management

| Aspect | Current (JWT) | New (Convex) |
|--------|---------------|--------------|
| Storage | localStorage | Convex manages (httpOnly cookies) |
| Expiry | Manual check | Automatic refresh |
| Logout | Clear token | `signOut()` function |
| User data | `user` from context | `useConvexAuth()` hook |

## Component Design

### OTPLoginForm.tsx

- Email input field with validation
- "Send Code" button with loading state
- Error display
- Matches current LoginForm styling (TailwindCSS)
- i18n support via useTranslation

### OTPVerifyForm.tsx

- 6-digit code input
- "Verify" button with loading state
- "Resend code" link with 60-second cooldown timer
- "Use different email" link to go back
- Error display for invalid/expired codes

### ConvexClientProvider.tsx

```tsx
<ConvexProvider client={convex}>
  <ConvexAuthProvider>
    {children}
  </ConvexAuthProvider>
</ConvexProvider>
```

### AuthContext Compatibility

Keep the interface similar so other components don't break:

```tsx
// These keep working:
const { user, isLoading, logout } = useAuth();

// Removed (no longer needed):
// login(username, password) → replaced by OTP flow
// register(username, password) → replaced by OTP flow
// token → Convex manages sessions internally
```

## Error Handling

### OTP-Specific Errors

| Error | User Message | Handling |
|-------|--------------|----------|
| Invalid email format | "Please enter a valid email" | Client-side validation |
| OTP expired (5-10 min) | "Code expired. Request a new one." | Show resend button |
| Invalid OTP code | "Invalid code. Please try again." | Allow retry, track attempts |
| Too many attempts | "Too many attempts. Try again later." | Cooldown period |
| Rate limited (Resend) | "Please wait before requesting another code." | Disable button with timer |
| Network error | "Connection failed. Please try again." | Retry button |

### Resend Cooldown

- 60-second cooldown between OTP requests
- Visual countdown timer
- Prevents abuse and Resend rate limits

### Session Edge Cases

| Scenario | Behavior |
|----------|----------|
| Session expires while using app | Redirect to login, preserve URL for return |
| Multiple tabs | Sessions sync automatically (Convex handles) |
| Offline | Show offline indicator, queue actions |

## Migration Strategy

### Steps (in order)

1. **Install & configure Convex** (no breaking changes yet)
2. **Create Convex auth backend** (schema, auth.ts, OTP config)
3. **Add ConvexClientProvider** (wrap app, coexists with old auth)
4. **Build new OTP components** (OTPLoginForm, OTPVerifyForm)
5. **Update AuthContext** (switch to Convex, keep interface)
6. **Test end-to-end** (login, logout, protected routes)
7. **Remove old auth code** (Express routes, SQLite users)

### Rollback Plan

- Git branch for entire migration
- Old auth code not deleted until new auth verified
- Can revert branch if issues arise
